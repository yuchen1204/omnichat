# OmniChat Internationalization (i18n) Design

**Date:** 2026-06-01
**Status:** Approved

## Summary

Implement full internationalization for OmniChat using Android standard `strings.xml` as the primary system, with English as the default language and Chinese Simplified as secondary. The existing `uiText()` system is retained only for AI-overridable decorative strings.

## Goals

- English as primary/default language, Chinese Simplified as secondary
- System locale detection — no in-app language toggle
- Full scope: UI strings, README/docs, DB entity defaults, non-UI code strings
- Hybrid architecture: Android `strings.xml` for standard strings + `uiText()` for AI overrides only

## Architecture

### String Resource Files

```
res/values/strings.xml          ← English (default, primary)
res/values-zh-rCN/strings.xml   ← Chinese Simplified (secondary)
```

### Naming Convention

Convert existing dot-notation `uiText()` keys to Android resource format:
- `topbar.title.chat` → `@string/topbar_title_chat`
- `chat.input.hint` → `@string/chat_input_hint`
- `action.cancel` → `@string/action_cancel`
- Legacy hex keys (e.g., `chat.4c423b81`) → meaningful names during migration

### Compose Usage

```kotlin
// Standard strings — Android i18n
Text(stringResource(R.string.action_cancel))

// AI-overridable decorative strings — existing uiText() system
Text(uiText("topbar.title.chat", "Chat"))
```

## Scope of Changes

### A. UI Strings (Compose Screens)

**Current state:** ~340 `uiText()` call sites across 21 files, plus residual hardcoded Chinese in ModelsConfigScreen, McpConfigScreen, ExportImportScreen, InterventionInput.

**Migration:**

1. **Standard strings (~300 keys):** Replace `uiText("key", "default")` → `stringResource(R.string.key)`. These are functional strings — button labels, error messages, form labels, status text.

2. **AI-overridable strings (~30-50 curated keys):** Keep `uiText()` with English defaults. These are decorative/personality strings users might want AI to customize — top bar titles, welcome messages, descriptive labels.

3. **Remaining hardcoded Chinese:** Strings not yet wrapped in any system get migrated directly to `stringResource()`.

### B. DB Entity Defaults

| Entity | Field | Current Default | Change |
|--------|-------|----------------|--------|
| `WorkspaceSession` | `title` | `"新工作区"` | Store `"__res:default_workspace_title"`, resolve at display |
| `AgentInstance` | `agentName` | `"主控 Agent"` | Store `"__res:default_agent_name"`, resolve at display |
| `WorkspaceTeam` | `teamName` | (user-entered) | No change |

**Resolution pattern:** Detect `__res:` prefix at display time, strip prefix, resolve via `context.getString()`. User-entered content (session titles, memory, presets) is never touched.

### C. Non-UI Code Strings

**Current state:** Chinese strings in ViewModels (`ChatViewModel`, `SettingsViewModel`), `AgentRunner`, `BuiltinToolHandler`, etc.

**Approach:**
- **ViewModels:** Use `getApplication<Application>().resources.getString(R.string.xxx)` via `AndroidViewModel` (most already extend it)
- **Non-ViewModel classes** (`BuiltinToolHandler`, `AgentRunner`, `ToolOrchestrator`): Accept `Resources` or `Context` as constructor parameter

### D. README / Documentation

- `README.md` — English version (primary, default for GitHub)
- `README_zh.md` — Chinese version (translated from current README)
- Cross-links at top of each file: `[中文版](README_zh.md)` / `[English](README.md)`
- `CLAUDE.md` and `AGENTS.md` stay English (developer/AI tooling docs)

### E. Build & Tooling

- **`generateUiTextKeys` Gradle task:** Modify to only track keys remaining in the `uiText()` system (~30-50 AI-override keys)
- **`ui_text_keys.json`:** Shrinks from ~340 to ~30-50 curated AI-override entries
- **`UiStrings.kt`:** No structural changes — `LocalUiStrings` and the overrides map continue for AI overrides
- **New files:** `res/values/strings.xml` (English), `res/values-zh-rCN/strings.xml` (Chinese)

### F. MCP Tool Descriptions

All 35 built-in MCP tool descriptions in `McpRuntimeManager.kt` stay English. These are consumed by LLMs, not displayed to users. No changes needed.

## Migration Order

1. Create `res/values/strings.xml` (English) with all ~340 keys translated
2. Create `res/values-zh-rCN/strings.xml` (Chinese) with existing Chinese defaults
3. Bulk-replace `uiText("key", "...")` → `stringResource(R.string.key)` for standard strings in all 21 Compose files
4. Wrap remaining hardcoded Chinese in `stringResource()` calls
5. Curate AI-override keys — keep ~30-50 in `uiText()` with English defaults
6. Update `ui_text_keys.json` to contain only AI-override keys
7. Update `generateUiTextKeys` Gradle task scope
8. Add `__res:` prefix resolution for DB entity defaults
9. Migrate non-UI Chinese strings in ViewModels/handlers to `Resources.getString()`
10. Create `README.md` (English) and rename current to `README_zh.md`

## Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Primary system | Android `strings.xml` | Native locale handling, IDE support, lint checks, translation tooling |
| AI overrides | Keep `uiText()` | Preserves runtime AI customization capability |
| Language switch | System locale only | Simpler UX, no settings to maintain |
| DB defaults | `__res:` prefix pattern | No schema migration needed, backwards compatible |
| Non-UI strings | `AndroidViewModel.resources` | Already available, no new dependency |
| MCP descriptions | Stay English | LLM-facing, not user-facing |
