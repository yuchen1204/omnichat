# Project Knowledge 与项目会话改造设计

## 1. 目标

调整现有“项目”功能，使用户能够在项目内管理知识资产，并创建只受项目作用域约束的项目会话。

目标流程：

1. 用户点击项目入口，进入项目列表。
2. 用户创建或打开项目，进入项目详情页。
3. 点击 **Project Knowledge**，进入项目资源页。
4. 项目资源页列出用户上传及 Agent 创建的全部项目资产；用户可上传和删除，但不能修改。
5. 返回项目详情页后，用户点击右下角 **创建新会话**，创建项目会话。
6. 项目会话只在项目页面内展示，不出现在普通聊天侧边栏。

## 2. 已确定的产品规则

### 项目资产

- 用户可上传：图片、PDF、DOC、DOCX、TXT、MD。
- Agent 可创建：TXT、MD、DOC、DOCX。
- 上传文件复制到 OmniChat 应用私有目录，不依赖原始 URI 的持续授权。
- 资源列表显示名称、类型、来源和创建时间；不显示文件大小。
- 来源分为“用户上传”和“Agent 创建”。
- 用户可以删除资产，但不能编辑、重命名、覆盖或修改内容。
- 删除资产时同时删除数据库记录和本地文件。
- Agent 通过项目资产工具按需查看资产，不自动把全部文件内容注入上下文。

### 项目会话

- 一个项目可以有多个项目会话。
- 会话消息彼此独立，但共享所属项目的全部资产和唯一项目记忆文件。
- 项目会话只从项目页面进入，只出现在当前项目的会话列表。
- 普通聊天侧边栏必须排除项目会话。
- 删除项目时，级联删除项目会话、项目资产、资产文件和项目记忆文件，并进行二次确认。

### 项目记忆

- 每个项目只有一个 Markdown 记忆文件 `project_memory.md`。
- 同项目所有项目会话共享该文件。
- Agent 可以通过专用工具读取、追加、替换和删除记忆内容。
- 用户只能查看记忆内容，不能编辑、删除或创建记忆文件。
- 项目记忆与全局长效记忆完全隔离，项目会话不能读写全局记忆。
- 多会话并发写入必须串行化，并使用临时文件加原子替换，避免损坏现有内容。

### 工具权限

项目会话采用严格白名单，只允许：

1. 项目资产工具：列出、读取当前项目资产；Agent 创建项目资产。
2. 项目记忆工具：读取和维护当前项目的 `project_memory.md`。
3. MCP 工具：继承全局当前启用的 MCP，并排除项目级禁用的 MCP 服务器。

项目会话禁止使用普通文件系统、全局记忆、联网、UI 调整、定时器、子 Agent、工作流及其他内置工具。工具执行层必须再次校验会话类型、项目归属和资源归属，不能只依赖模型遵守提示。

MCP 的有效集合为：

```text
全局当前启用的 MCP 服务器 - 当前项目明确禁用的 MCP 服务器
```

默认继承全部全局启用的 MCP。项目详情页提供 MCP 配置入口，可逐个关闭服务器。全局状态变化后，项目会话使用最新的全局启用状态；项目级关闭只影响当前项目。

## 3. 数据模型

在现有项目实现基础上扩展或调整：

### Project

保存项目名称、描述、时间字段和项目级 MCP 禁用服务器列表。禁用列表使用现有项目配置约定保存，推荐 JSON 字符串以兼容 Room 实体的持久化方式。

### ProjectAsset

建议字段：

- `id`
- `projectId`
- `fileName`
- `mimeType`
- `localPath`
- `source`（`USER_UPLOAD` / `AGENT_CREATED`）
- `createdAt`

文件路径使用项目私有目录，例如：

```text
/files/projects/{projectId}/{assetId}_{safeFileName}
```

数据库记录与文件系统操作由 Repository 统一管理，不允许 UI 或工具自行拼接路径绕过权限校验。

### Session

增加可空 `projectId`：

- `projectId == null`：普通会话；
- `projectId != null`：项目会话。

项目会话不再需要重复的 `isProjectSession` 字段，避免两个字段不一致。项目删除时级联删除关联会话。

### ProjectMemory

项目记忆是单文件资源。数据库可保存 `projectId`、`localPath` 和 `updatedAt`，或由确定性的项目目录路径管理；无论采用哪种方式，首次 Agent 写入时都应自动创建文件，项目删除时清理文件。

## 4. 组件与数据流

### UI

- `ProjectScreen`：项目列表、创建项目、打开项目、删除项目。
- `ProjectDetailScreen`：项目概览、Project Knowledge、Project Memory、MCP 设置、项目会话列表和创建新会话按钮。
- 新增或拆分 Project Knowledge 页面：资源列表、Android 文件选择器上传、删除确认。
- 新增或复用项目记忆只读页面：展示 Markdown 内容。
- 新增项目级 MCP 设置页面或对话框：展示全局已启用服务器，并保存项目禁用列表。

### Repository/DAO

提供项目、资产、项目会话和项目配置的响应式查询与变更操作。项目删除必须通过单一事务/协调流程完成数据库级联和本地文件清理；文件删除失败需要显式记录或返回错误，不能静默声称清理成功。

### 项目工具

提供以下受项目作用域约束的能力：

- `project_list_assets`：列出当前项目资产的 ID、名称、类型、来源和时间。
- `project_read_asset`：校验资产属于当前项目后读取 TXT/MD/PDF/DOC/DOCX；图片以视觉输入可消费的形式返回。
- `project_create_asset`：Agent 创建 TXT/MD/DOC/DOCX；禁止覆盖已有资产，允许同名但使用新的内部 ID 和路径。
- `project_read_memory`：读取当前项目唯一 Markdown 记忆文件。
- `project_update_memory`：对记忆执行追加、替换、删除等操作，并保证原子写入。

资产删除默认只向用户开放，不向 Agent 开放。

### ChatViewModel/ToolExecutor

打开或发送项目会话消息时，根据 `session.projectId` 构造项目权限上下文：当前项目 ID、资产访问范围、项目记忆路径和允许的 MCP 服务器。工具注册/导出和执行入口都需要应用白名单；执行时再次验证资产归属与 MCP 全局/项目状态。

普通会话路径不得获得项目上下文，也不得看到项目专用工具。普通会话查询和侧边栏查询必须明确排除 `projectId != null` 的会话。

### 文档读取复用

项目资产工具负责权限校验、类型校验和资产路径解析，再复用现有 PDF、DOC/DOCX、文本和图片读取逻辑。不能把通用文件系统工具暴露给项目会话来实现读取，否则会绕过项目边界。

## 5. 错误处理与一致性

- 资产不存在或已删除：返回明确的不可用错误。
- 资产不属于当前项目：返回统一权限错误，不泄露其他项目是否存在。
- 类型不支持：返回支持的类型列表。
- 解析失败：保留资产记录并返回解析错误，不返回虚假的成功结果。
- 同名 Agent 资产：允许，使用新 ID 和路径。
- 用户删除正在读取的资产：当前读取失败，后续列表不再出现。
- 项目删除期间创建资产：Repository 拒绝操作。
- MCP 全局关闭后：项目会话立即不能调用该服务器。
- 项目记忆并发更新：Repository/Memory 层串行化写入；先读取最新内容，写入临时文件后原子替换，失败时保留原文件。

## 6. 测试设计

### 数据层

- 创建、查询、更新和删除项目及项目资产。
- 项目会话正确关联项目，普通会话查询排除项目会话。
- 多项目会话共享同一资产列表和记忆文件。
- 删除项目级联删除数据库记录、本地资产和记忆文件。

### 权限层

- 项目会话只能使用项目工具和有效 MCP。
- 普通会话不能使用项目资产或项目记忆工具。
- 项目会话不能使用普通文件、全局记忆、联网、UI、子 Agent 和工作流工具。
- 伪造其他项目资产 ID 不返回内容。
- 项目禁用 MCP 后无法调用对应服务器；全局禁用后同样不能调用。

### 资源层

- 文件选择器支持六种用户上传类型。
- 上传复制到应用私有目录。
- TXT、MD、PDF、DOC/DOCX 能被项目工具读取；图片能以视觉输入读取。
- Agent 能创建四种允许的文档类型，不能覆盖资产。
- 删除资产同时清理数据库记录和文件。

### UI/流程

- 项目入口、项目列表、创建和删除确认。
- Project Knowledge 列表、上传、来源展示和删除。
- Project Memory 只读展示。
- MCP 继承与项目级关闭。
- 创建新项目会话、项目内打开和多会话列表。
- 项目会话不出现在普通聊天侧边栏。

## 7. 实施范围与顺序

采用“在现有 Project 实现上扩展”的方案，不重做无关功能。建议按以下顺序实施：

1. 核对并调整现有 Room 实体、迁移、DAO 和 Repository，确保项目、资产、会话和配置边界正确。
2. 完成应用私有目录资产存储、项目记忆文件服务和级联清理。
3. 完成项目工具及统一工具执行层的项目权限白名单。
4. 完成 Project Knowledge、Project Memory、MCP 设置和项目会话 UI 流程。
5. 接入 ChatViewModel 的项目上下文，补充普通侧边栏过滤。
6. 添加单元测试并执行 debug build 与测试验证。

不在本次范围内：MCP 直接访问项目资产的桥接、项目资产在线预览、用户编辑/重命名资产、多个项目记忆文件、项目会话出现在普通聊天入口。
